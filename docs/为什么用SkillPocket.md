# 为什么用 Skill Pocket

好用的 AI Skill 和模型越来越多，但找起来难、记起来乱、选起来慢。Skill Pocket 针对这三件事，提供三个核心能力：

| | 痛点 | Skill Pocket 怎么解决 |
|---|---|---|
| 一 | GitHub 是英文的，用中文搜不准、看不懂 | **GitHub 的中文中转站**：中文需求转成英文去搜，英文结果再转回中文 |
| 二 | 看到好东西随手记在抖音、小红书、相册里，过后找不到 | **一个口袋统一收藏**：截个图就能收进来，用名称、网址、意思都能搜回来 |
| 三 | 几个差不多的工具摆在面前，只能挨个去试 | **AI 智能对比**：按多个维度对比优劣，按使用场景直接给出推荐 |

---

## 一、GitHub 的中文中转站

### 痛点
GitHub 上的项目几乎都是英文的，搜索也只按字面匹配关键词。用中文描述需求去搜，基本搜不到；把需求逐字翻译成英文去搜，常常因为用词和开发者习惯的叫法不一样而漏掉好项目。搜到之后，还要一篇篇读英文 README 才能判断能不能用。

### Skill Pocket 的做法：两次语言转换

**第一次：把你的中文需求，转换成 GitHub 上真正会用的英文搜索词。**

你只需要用一句中文说出需求，例如「帮我把会议录音整理成纪要」。AI 会：
1. 先用一句中文复述它理解的需求，让你确认它没理解错；
2. 判断你是在找**某个具体项目**、按**功能**找，还是一次列了**好几个项目**，用不同的方式去搜；
3. 生成 **3~5 组英文搜索词**，覆盖同义词、领域术语和开发者常见的命名方式，而不是逐字翻译。比如同一个需求会同时用 `meeting minutes`、`transcript summarizer`、`speech to notes` 等不同说法去搜；
4. 必要时加上 GitHub 的搜索条件（如话题、编程语言、星标数），过滤掉无关项目；
5. 如果需求可能对应某个 Agent Skill，同时去 Skill 目录站 skills.sh 查找。

**为什么更准**
- **多路搜索，不漏**：一个需求同时用几种英文说法搜，合并去重，单一关键词搜不到的项目也能被找出来。
- **AI 逐个打分，不乱**：所有候选由 AI 对照你的原始需求按 0~100 打分，**低于 50 分的直接不显示**。打分只看是否满足需求，不会因为星标多就排在前面；你点名要找的项目始终排第一。
- **省额度**：搜索结果缓存 24 小时，同样的需求不会重复消耗 GitHub 搜索次数。

**第二次：把英文的搜索结果，转换成中文给你看。**
- **简洁版**：每个结果附一句中文说明，讲清它是什么、为什么符合（或不符合）你的需求，扫一眼就能挑。
- **详细版**：收进 Skill Pocket 的项目，AI 会通读 README，整理出：
  - 一句话中文简介（40 字以内）；
  - 150~400 字的中文功能介绍：能做什么、适合什么场景、有什么特点；
  - 分步骤的中文安装说明，命令可以一键复制；
  - 上了榜单的项目还有一段 60~120 字的中文详解。
- 专有名词、命令和代码保留原文，避免翻译走样。

结果就是：**用中文提需求，看中文结果，不用读英文也能在 GitHub 上找到合适的项目。**

## 二、一个口袋，统一收藏好用的 Skill 和模型

### 痛点
刷短视频、看文章、逛社区时，经常看到「这个 Skill 太好用了」「这个模型效果惊人」。大多数人会顺手记下来：有人收藏在抖音，有人收藏在小红书，有人截图存在相册。过一段时间想用时，记不清在哪看到的，翻相册也找不到，收藏散落在各处，越积越乱。

### Skill Pocket 的做法：四种方式收进来，一个地方管起来

**最快的方式：截图收藏**

在任何地方看到感兴趣的内容——短视频、文章、朋友圈、别人分享的榜单——**截个屏**，上传到 Skill Pocket（网页；官方站点另有微信小程序）即可：
- 一张截图里有一个项目或一整张榜单都可以，一次最多识别 30 个；
- AI 识别出截图里的项目名称后，自动去 Skill 目录站 skills.sh 和 GitHub 核实，找到真正的来源仓库；截图里名称差一两个字母也能纠正过来；
- 已经收藏过的会提示「已收录」，不会重复添加；只是同名、来源不同的会提醒你自己确认；
- 识别结果里勾选想要的，点一下就收进口袋。

不用打字、不用搜索，**看到就截图，截图就收藏**。

**其他三种方式**

| 方式 | 适合什么时候 |
|---|---|
| **网址** | 手上有 GitHub 链接时直接粘贴；一个仓库里有多个 Skill 会拆开让你勾选。也可以粘贴一篇文章的链接或全文，AI 通读后把文中提到的项目都找出来 |
| **名称** | 知道项目名时直接搜名称 |
| **语义（按意思）** | 只记得它是干什么的，用一句话描述就能找到，例如「那个能把网页转成 PPT 的」 |

**收进来之后**
- 每个项目都有统一格式的中文介绍和安装步骤，不用再回原来的视频或文章里找。
- 收藏可以按自己的习惯分类，一个项目能放进多个分类；还能让 AI 帮你整理分类，确认后才生效。
- 收藏夹可以生成分享链接发给朋友，也可以导出成 Markdown 或 JSON。
- 收藏的项目原地址失效时会自动标记，不会留着一堆打不开的链接。

## 三、AI 智能对比，快速选出适合你的那一个

### 痛点
找到几个功能差不多的 Skill 或模型之后，往往不知道哪个更好。README 都说自己好，星标数也说明不了是否适合你。最后只能一个个安装、一个个试，花大量时间。

### Skill Pocket 的做法：多维度对比 + 按场景推荐

一次选 2~6 个条目（可以是口袋里收藏的，也可以是任意 GitHub 仓库），AI 会：

1. **先分组**：判断哪些是解决同一类问题、可以互相替代的，哪些其实是不同类型的东西。不同类的不硬比优劣，只说明各自适合什么时候用。
2. **逐个维度比较**同类项目，每个维度标出哪个更好：

   | 维度 | 看什么 |
   |---|---|
   | 定位与类型 | 它到底是什么 |
   | 核心能力 | 能做什么、做得怎样 |
   | 适用场景 | 适合什么情况下用 |
   | 上手难度 | 安装和使用的门槛 |
   | 运行环境与依赖 | 需要什么环境、依赖什么 |
   | 质量与活跃度 | 星标、近 30 天增长、最近更新时间 |
   | 成本 | 是否收费、资源消耗 |
   | 许可证 | 能否商用 |
   | 局限与风险 | 需要注意的问题 |

3. **给出上手方法**：每个项目 2~4 步的使用步骤。
4. **按场景推荐**：针对 2~3 个常见使用场景，分别推荐最合适的一个并说明理由。
5. **主动提醒风险**：已归档、超过一年没更新、或有安全风险的项目，会明确提醒。

AI 只根据项目的真实资料（介绍、README、安装方式、星标和更新数据、许可证）分析，资料里没有的会写「资料未提及」，不会编造。同样的一组项目 7 天内再次对比，直接复用上次的结果。

结果就是：**不用挨个试，几十秒就能看清差别，选出适合自己的那一个。**

## 其他能力

除了这三个核心能力，Skill Pocket 还提供：每天自动从 GitHub 发现新项目并生成分类日榜、周榜；评论与评分、语音输入；完整的管理后台（内容审核、用户管理、运行监控、数据分析）。具体用法见 [使用说明](使用说明.md)。
